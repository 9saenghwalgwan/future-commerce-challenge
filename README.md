# ALGOSA (알고사) · 알고 사는 쇼핑 에이전트

**내 사용 환경에 맞는지 알고, 내 결제 조건에서의 진짜 가격을 알고 사도록 돕는 AI 쇼핑 에이전트 아이디어.**

Future Commerce Challenge 2026 · Track A. Future Shopping Experience · 2026-11-22 · 2인 팀(9생활관) · **예선 탈락**(본선 미진출)

> 현장 작업 시간 3시간(14:00~17:00)의 아이디어톤 결과물이다. 실제 AI 검색과 결제는 연결하지 않았고, 프로토타입은 흐름을 보여 주는 시연용이다.

## 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 문제 | 사용 환경이 얽힌 상품(예: 컴퓨터 두 대를 모니터 하나로 쓰게 해 주는 KVM 스위치)은 AI에게 채팅으로 물으면 질문이 길어지고 결론만 남는다. 팀원의 실제 구매 기록에서 질문은 25번, 선택 변경은 5번, AI의 정정은 2번이었다. 판매처마다 결제창 가격도 표시가와 달랐다. |
| 해결 | 대화를 **이해 지도**로 남긴다. 단계마다 노드가 생기고, 내 조건은 화면에 계속 보인다. 같은 상품의 판매처별 가격은 **결정 보드**에서 표시가, 결제창 금액, 청구할인 후 금액으로 나눠 비교한다. 에이전트는 결제 버튼 직전에서 멈추고, 결제는 사용자가 한다. |
| 결과 | 예선(제출 자료 심사)에서 탈락했다. |
| 기술(구상) | 답에 따라 다음 질문을 고르는 LLM, 구조화 출력으로 그리는 선언형 UI, 로그인한 결제창을 읽는 화면 에이전트, 가격 조합은 LLM이 아닌 일반 코드로 계산. 시연물은 HTML·CSS·JS만으로 만들었다. |

## 결과

- 예선(17:00~18:00)은 제출 자료만으로 심사했고, 트랙별로 최대 5팀이 본선에 올랐다. 우리 팀은 본선에 가지 못했다.
- 심사표(100점): 공통 70점(문제·커머스 가치 20, AI를 쓰는 이유 20, UX 구체성 15, 논리성·실현성 15) + Track A 30점(편리·재방문 15, 안심 위임 15)
- 본선에서 본 수상 3팀의 공통점: 1·2등은 서비스를 직접 실험해 효과를 검증한 결과를 보여 줬다. 3등은 대회가 강조한 '신뢰'를 별도 장표로 정리했다. 1등의 발표 자료는 텍스트 위주였다. 디자인보다 **검증**과 **심사 기준 대응**이 앞섰다.

## 회고

### 잘한 것 (Keep)

- **대회 전에 리서치를 해 뒀다.** 커뮤니티 쇼핑 글 2,551건을 불편 유형별로 분류하고, 타깃 후보 10개에 점수를 매겼다. 덕분에 당일 논의를 근거에서 시작했다.
- **실제 기록을 이야기의 뼈대로 썼다.** 지어낸 장면 대신 팀원의 KVM 구매 대화([KVM_구매_검토_과정.md](KVM_구매_검토_과정.md))로 문제를 보여 줬다.
- **빠르게 합치고 결정을 기록했다.** 두 사람이 따로 낸 아이디어('이해', '진짜 가격')를 15:00 무렵 하나로 합쳤다. 결정은 시각과 함께 [PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md)와 PRD에 적었다.
- **심사표로 우선순위를 정했다.** 15:20에 심사표 기준으로 자기 평가를 돌려 고칠 순서를 정했다.
- **컨셉을 화면으로 보여 줬다.** 질문을 입력하면 단계마다 노드가 남는 이해 지도가 '대화 대신 지도'를 그대로 보여 줬고, 같은 화면 안에서 결정 보드로 이어졌다.
- **결제는 사용자에게 남겼다.** 에이전트가 결제 버튼 직전에서 멈추는 것을 기본값으로 설계했다. 적립금은 현금 가격과 나눠 순위를 매겼고, 만족도나 최적성을 보장한다고 쓰지 않았다.

### 아쉬운 것 (Problem)

- **'다음'만 누르면 해결책을 볼 수 없었다.** 제출본 12장 중 8번 장이 프로토타입인데, 질문을 입력해야 움직인다. 자료를 넘기기만 하는 심사자에게는 제목·컨셉·문제를 다룬 앞의 7장, 빈 입력창, 마무리 4장만 보인다. 결정 보드와 '결제 직전 멈춤'은 데모 안에만 있었다.
- **신뢰와 결제 흐름을 다룬 장이 제출본에 없었다.** 제출 요건(사용자·AI·상품·결제 흐름 설명)과 Track A 안심 위임 15점에 대응하는 장이 없었다. 데모 밖에서는 기대효과 카드의 한 줄("결제는 내가 하니 안심하고 맡겨요")이 전부였다.
- **덱이 세 개로 갈라졌고, 다 갖춘 덱을 내지 않았다.** 신뢰 장표(주최 측 4단계 구조)와 솔루션 장표는 정적 덱(16:37)과 병합 덱(16:58)에 있었다. 하지만 마지막 30분에 두 사람이 각자 병합했고, 제출된 건 그 장표가 없는 인터랙티브 덱이었다. 제출본을 누가, 언제 확정할지 정해 두지 않았다. 제출본은 마감 직후까지 고쳤다(커밋 17:34).
- **PRD와 발표 자료가 따로 놀았다.** 데이터 경로(로그인한 결제창 읽기), 위임 범위, 4단계 구조가 PRD에는 있었지만 제출본에는 없었다.
- **제출본은 마감 뒤에야 심사표로 평가했다.** 15:20 자기 평가는 PRD와 가격 페이지가 대상이었다. 제출본 평가는 18:25에 했고, 결과는 61/100이었다.
- **실험이 없었다.** 효과를 검증한 결과가 없었다. 수상팀은 작은 실험으로 효과를 보였다. 대회 전에 계획했던 결제창 실측도 결과로 남기지 못했다.
- **주인공 메시지가 둘이었다.** '환경에 맞는지 알고'와 '진짜 가격을 알고'를 함께 내걸었다. 데모가 이해 병목 위주였으니 발표도 이해 병목 하나로 끌고 갔어야 했다. 마지막 1시간에는 주인공 재정의(15:55), 시연 상품 교체(16:10), 도입부 변경(16:15)이 이어졌다.
- **타깃이 넓었다.** 마무리 4장 중 2장을 '모든 구매에는 이해가 있다'와 옷 구매 예시에 썼다. 리서치 1순위였던 해외직구를 택하지 않은 이유도 적어 두지 않았다.
- **핵심 기능 3개를 한 장에 정리하지 않았다.** 이해 지도, 계속 보이는 내 조건, 결정 보드가 데모 안에 흩어져 있었다.
- **숫자 하나를 실측처럼 썼다.** "알리 63,648원 → 내 결제창에선 73,712원"이라고 썼지만, 기록에서 73,712원은 원래 가격이 "적용될 수 있다"는 안내였다. 실제 구매는 63,648원(신규 회원가)이었다.
- **배운 것을 또 놓쳤다.** 지난 해커톤의 기획 강의에서 배운 세 가지를 시간 압박 속에서 다시 빠뜨렸다. 타깃 한 명, Must 3개(핵심 기능 3개), 장표마다 심사 기준 표시다.

## 다음 해커톤에 가져갈 것 (Try)

1. **제출본은 하나, 담당자도 한 명, 마감 60분 전 동결.** 병합은 한 사람만 한다. 동결한 뒤에는 제출할 링크를 다른 기기나 시크릿 창에서 열고, '다음'만 눌러 끝까지 넘겨 본다.
2. **'다음'만 눌러도 이야기가 끝나게 만든다.** 문제 → 해결(핵심 기능 3개) → 신뢰 → 결제 흐름을 클릭 없이 장표 본문에 둔다. 데모는 캡처를 순서대로 놓거나 자동 재생으로 장표 안에서 펼쳐 보이고, 직접 조작은 덤으로 둔다.
3. **심사표 점검표를 만든다.** 심사 항목과 제출 요건마다 담당 장표를 대응시키고, 자기 평가는 PRD가 아니라 제출본에 돌린다. 대회가 강조하는 키워드(이번에는 신뢰)는 전용 장표로 만든다.
4. **주인공 메시지는 하나.** 데모의 주인공, 발표의 주인공, 표지의 훅을 같은 메시지로 맞춘다. 표지는 궁금증을 만드는 질문으로 연다.
5. **핵심 기능 3개를 카드 한 장에.** 카드마다 어떤 페인 포인트를 푸는지 잇는다.
6. **작은 실험을 하나 넣는다.** 예: 같은 KVM 과제를 몇 명에게 채팅과 이해 지도로 각각 풀게 하고, 고른 이유를 설명할 수 있는지 비교한다. 검증하지 않은 숫자는 '예시'로 표시한다.
7. **타깃 한 명, 상황 하나.** 다른 상품으로의 확장은 마지막 한 장에만 둔다. 리서치 1순위를 버릴 때는 이유를 적는다.
8. **차별점 장표를 둔다.** 기존 가격 비교 서비스, 기존 AI 쇼핑 에이전트와 무엇이 다른지 한 장에 보여 준다.
9. **제출본을 저장소에 두고 README에 여는 법을 적는다.** 제출 링크의 내용과 저장소의 제출본이 같아야 한다.

### 제출 전 점검표

- [ ] 제출본과 담당자가 하나로 정해져 있고, 마감 60분 전에 동결했다
- [ ] 제출 링크를 내 컴퓨터가 아닌 기기(또는 시크릿 창)에서 열었다
- [ ] '다음'만 눌러도 문제 → 해결(핵심 기능 3개) → 신뢰 → 결제 흐름이 보인다
- [ ] 팀 밖의 한 사람(또는 AI 평가)이 자료만 보고 서비스를 한 문장으로 다시 설명했다
- [ ] 심사 항목과 제출 요건마다 담당 장표가 있다
- [ ] 장표의 숫자마다 출처 종류(실제 기록·외부 사례·예시)가 붙어 있다
- [ ] 제출본이 저장소에 있고, README에 여는 법이 있다

### 발표 자료 기본 틀
